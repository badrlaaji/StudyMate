# StudyMate

> **Work in progress.** Steps 0-6 done: indexed book, 21 notions, retrieval evaluation, fine-tuned embeddings, LangGraph agent with verified citations.

A study assistant for one textbook. It answers questions with **cited and verified pages**,
routes each request (answer, quiz, revision plan), checks your understanding with a
**Feynman mode**, and tracks a **mastery map** of the course notions. English and French.

## Problem

Asking a general chatbot about a course gives fluent answers with no way to check them
against the textbook. Students need answers grounded in *their* book, with page numbers
they can open, and feedback on what they have actually understood.

## Results so far

**Retrieval** (step 4) — 20 test questions, each asked in English and in French, written by
paraphrasing the book (not generated by the LLM). Expected answer = a PDF page. No LLM in this
evaluation: `multilingual-e5-small` embeddings + exact cosine search in pgvector, 284 chunks.

| Embeddings | Language | hit@4 | MRR@10 |
| --- | --- | --- | --- |
| e5-small (base) | English | 0.850 | 0.703 |
| e5-small (base) | French | 0.750 | 0.604 |
| e5-small fine-tuned (step 5) | English | 0.950 | 0.722 |
| e5-small fine-tuned (step 5) | French | 0.800 | 0.611 |

- hit@4: share of questions with a correct page in the top 4 chunks; MRR@10: mean of 1/rank of
  the first correct page (0 if not in the top 10).
- French questions retrieve English pages less well (−0.099 MRR). Misses are mostly paraphrases
  that avoid the book's term ("a model too simple for the data" for *underfitting*).
- Out-of-course questions get top-1 scores (0.75–0.86) overlapping in-course ones (0.81–0.90):
  a score threshold cannot detect them; refusal is handled by the agent (step 6).
- Fine-tuning (step 5): 560 synthetic question-passage pairs (English + French, generated by
  Gemini, decontaminated against the evaluation questions), `MultipleNegativesRankingLoss`,
  2 epochs on CPU (7 min). hit@4 improves (+2 English, +1 French questions out of 20), MRR
  barely moves; per question, ranks go both ways. Indicative only on 20 questions.
- Reproduce: `uv run python -m eval.eval_retrieval test` (reports in `eval/results/`).

**Answers** (step 6) — the LangGraph agent on the same 20 test questions (+ 5 out-of-course
traps), fine-tuned embeddings. *Correct* = the answer passed the citation check (cited pages
are among the retrieved ones) **and** cites an expected page. No LLM judge.

| Language | Correct | Expected page in top 4 | Traps refused |
| --- | --- | --- | --- |
| English | 19/20 | 19/20 | 5/5 |
| French | 19/20 | 19/20 | 5/5 |

- The router also rewrites the question as an English search query (same LLM call): French
  questions reach the right page in the top 4 for 19/20 instead of 16/20.
- The one miss (both languages) cites a verified but wrong page: the citation check proves the
  page was retrieved, not that it is the best one.
- Reproduce: `uv run python -m eval.eval_answers`.

## Stack

- **Python 3.13** (uv): FastAPI, LangGraph, LangChain, sentence-transformers, PyTorch (CPU), pypdf
- **LLM**: Google Gemini (`gemini-3.5-flash-lite`), structured outputs validated with Pydantic
- **Embeddings**: `intfloat/multilingual-e5-small`
- **Database**: PostgreSQL + pgvector (Neon in development), asyncpg
- **Front end**: Next.js 16, React 19, react-pdf, Recharts
- **Mastery service**: Spring Boot 4.1, Java 21
- **CI**: GitHub Actions, Docker Compose

## Setup (Windows, PowerShell)

```powershell
uv venv --python 3.13
.\.venv\Scripts\Activate.ps1
uv pip install torch==2.14.1 --index-url https://download.pytorch.org/whl/cpu
uv pip install -r requirements.txt -r requirements-dev.txt
Copy-Item .env.example .env   # then fill in the keys
uv run python -m scripts.check_env all
```
